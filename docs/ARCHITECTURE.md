## Data and trust boundaries

The gateway issues an opaque HttpOnly cookie and hashes it to a public member ID. It overwrites forwarded identity headers and rejects cross-origin writes/WebSocket upgrades. Each SQLite Durable Object stores one current room JSON row, bounded command IDs/timestamps and a short throttle table. No uploaded media bytes or voice recordings are persisted. There is no migration for optional room metadata; legacy rooms default to public.

Private rooms use an independent random invitation capability, not the room epoch. The fixed lobby still reveals that a slot is occupied, but hides title/capacity/member count. Only a valid link can create a pending request; host approval remains mandatory. Existing admitted/pending cookie holders can resume. Explicit rotation cancels old pending requests; ordinary approved members receive no capability. This is capability-based admission, not end-to-end encryption or an account/login system.

Transport membership has a server-only 90s lease renewed by existing clock probes with 30s write coalescing and no room revision/broadcast. Close callbacks retain ≤30s of grace, bounded by the lease. Expired host transfers only to the designated live successor or closes the room; legacy orphan rooms close on sweep. New requests are blocked during host recovery. Client recovery is serialized, bounded, backoff-based and ignores callbacks from replaced sockets/epochs; pagehide closes transport without an unload room-delete request.

Peer poses are ephemeral WebSocket data, cached in the browser by room epoch/member and refreshed every 2 seconds for late joiners. Older room snapshots cannot replace a live pose; identical heartbeats do not rerender. Poke commands use the normal authenticated command path, approved-peer targeting and a 3-second actor cooldown. `RoomActivity.tsx` deduplicates recipient-only poke audio, authenticated-sender chat previews (max 3 / 6s) and shared reaction IDs. The single optional reaction has a 3s expiry scheduled by the DO alarm, plus a 5s per-sender cooldown; it is never appended to chat/history. `Fireworks.tsx`/`shared/fireworks.ts` replace the flower shower (wire `flowers`) with three bounded CSS bursts; `fireworkSound.ts` shares their fuse schedule and skips expired cues. `useRoomSounds.ts` owns gesture-unlocked, muted WebAudio cues, cancels pending fireworks on mute/session change and disposes nodes; no recordings or audio assets are stored. Approval preempts the required start dialog; `useModalFocus.ts` restores focus when a decided row disappears.

The Worker coordinates playback time and source identity, not codecs or decoding. Remote HTTPS media loads directly in each browser. Local files attempt reliable WebRTC; the explicit bounded WS fallback is tested where managed Chromium blocks UDP. The current file starts after full receipt, then catches up. Removing/finishing the item drops DB metadata and client resources. Drive preview is explicitly unsynchronized and has no ended API.

Clock estimates use the lowest RTT among up to eight samples younger than 60 seconds. Nonces are single-use and tied to socket plus epoch. Native and YouTube players read a stable monotonic server-time callback; camera/avatar wall-clock offsets are quantized to 10 ms to avoid idle redraws from tiny clock noise. Asymmetric network paths remain an estimation limit, not a certified drift bound.

The screen dimensions/plane/corners live in `shared/projection.ts`. The camera composes a signed-W clip-space CSS matrix for the single DOM player; partial camera-plane crossings remain visible, with only fully behind-camera screens hidden. Eye + orbit replace the four presets. Camera orbit angle is independent of bounded network head pose. The Canvas has alpha enabled, an opaque scene background and a transparent NoBlending depth-writing screen plane; foreground geometry keeps its opaque pixels, so video cannot paint over heads. Canvas pointer events pass through to the native player. Light mode is explicitly flat. Avatar materials clone per instance and recolor pinned atlas UV cells. Scene-volume quantization allows all skinned parts of one avatar to share an equal-bind skeleton and bone texture. Male scalp hair is derived offline from the pinned Rogue; prepare-avatars calls add-male-hair. Clones dispose without disposing shared maps/geometry. Seating uses five instanced batches; immutable seat layouts are cached. Walkway faces meet at boundaries; LEDs follow the same aisle height function.

## Verification boundaries

[Current plan](KE_HOACH_TRIEN_KHAI_HIEN_HANH.md) separates implemented source from device/provider/deployment gates. Browser UI tests mock YouTube/speech; native media tests decode generated WebM, MP3 and H.264 MOV and compare transferred bytes. The 10-avatar SwiftShader test is a rendering smoke, not a device FPS gate. Capacity tests cover 30 backend sockets, not 30 rendered media devices. All mutation tests run locally.

Keep `encodeBody: "manual"` in the optional embedded gzip release. Deploy only the existing Worker/account in PROJECT_STATE; never reset production rooms or change billing to run a test. The older proposed stack is [archived](archive/STACK_VA_KIEN_TRUC_V2.md).

Scene action entry: `QuickActions.tsx` owns the floating disclosure and per-sender cooldown UI; `RoomControls.tsx` retains camera/quality/personal ambience. `useHeadDrag.ts` tracks ≤2 captured pointers, batches look/zoom in RAF, and cancels on blur/cancel. Explicit gesture mode overlays video without remounting it; native player interaction returns when disabled. Shared floating icons/fireworks are bounded and frameless, with existing actor-private events and timed sound.
